# graphify-plus v6.0.0 — what changed and how to measure whether it worked

We rebuilt the contract with Claude. Four things changed. Here's how
to install them and verify whether they worked for you.

## What changed

1. **A long-running daemon.** Pre-computed indexes, sub-millisecond P50
   on small repos, freshness contract on every response, hybrid grep
   fallback when stale. `gp daemon start --detach` once per session.
2. **An intent-typed tool surface.** `who_calls`, `whats_in`,
   `what_depends_on`, `find_by_concept`, `find_by_name`,
   `whats_untested`, `plan` — all returning `file:line` so they pipe
   straight into Read/Edit. The legacy `query_graph` still works for
   one major version.
3. **A routing contract Claude can read.** `gp daemon install` drops
   `.claude/skills/graphify-plus/SKILL.md` and a `pre_grep_hook.py`
   that nudges (never blocks) toward the graph when grep would lose.
4. **Adoption telemetry.** The mechanism that lets you say, with
   evidence, whether the rewrite changed anything: `gp daemon
   adoption` reports graph-vs-grep call ratios, hook accept rates,
   and deltas vs. a stored baseline.

## How to install

```bash
pip install -U graphify-plus
cd your-project
gp migrate ./graphify-out --to 6.0      # if upgrading from v5.x
gp daemon quickstart .                  # init + warm + install hook + recipes
gp daemon start --detach
```

Then add the hook to `.claude/settings.json` (the snippet is in
`gp daemon quickstart` output).

## How to measure whether it worked

The point of v6.0 is one number. Capture today's state, run for a
week, look at the delta:

```bash
gp daemon adoption-baseline set --label v6.0
# ... a week of normal Claude Code use ...
gp daemon adoption --window-hours 168
```

You'll see:

- **`adoption_rate`** — graph_calls / (graph_calls + grep_calls).
  Target: >50% on structural queries.
- **`nudge_accept_rate`** — fraction of hook nudges followed by a
  graph call within 30 seconds. Tells you whether the *hook* is doing
  the work, vs. Claude learning the tool surface from `SKILL.md`.
- **`top_missed`** — the bareword grep patterns the daemon could have
  answered but didn't. The list of nudges to tune.
- **`vs baseline`** — the delta line. The number that says whether
  v6.0 changed Claude's behaviour vs. the prior state.

If `adoption_rate` is below 50% and `nudge_accept_rate` is below
20%, the routing skill is the next thing to tune. If `adoption_rate`
is above 50% but `nudge_accept_rate` is low, the hook is being
ignored and the win is coming from elsewhere — both useful to know.

## How to verify performance honestly

Two tables. Run both:

```bash
gp daemon perfcheck --workload all --report           # against your repo
python scripts/perfcheck_medium.py                    # 30k-symbol synthetic
```

The small-repo table is hot-cache best case. The medium-repo table
exposes the real tail-latency surface — and on this release shows a
known-issue 1-hop P99 of ~1.78s on 38k symbols (RISKS.md R13;
follow-up in v6.0.1).

## What's not in this release

Explicit, so nobody's surprised. See [`ROADMAP.md`](../ROADMAP.md):

- Slack live API ingest (JSON export ingest ships)
- Full Node.js CDP profiler client (SIGUSR1 + breadcrumb only)
- MLX profiler attach (detection only)
- Status-bar pill VS Code extension (data API ships)
- LLM-backed NL→GPL translator (rule-based fallback ships)
- Curated multi-repo benchmark corpus (tiny fixture only — Layer
  14.3 lands in v6.0.2)
- Homebrew tap (formula scaffold ships)

Each `🟡` line in `ROADMAP.md` names a target release.

## What's likely to break first

[`RISKS.md`](../RISKS.md) lists 13 post-merge failure modes with
symptom + root cause + follow-up. The top three to monitor:

- **R1** — watcher under heavy churn (`git pull` of hundreds of
  files spikes CPU and temporarily marks graph stale)
- **R6** — hook noise floor (now measurable via
  `nudge_accept_rate`; if it drops below 10% the hook needs a budget)
- **R13** — 1-hop tail latency on medium graphs (1.78s P99 on 38k
  symbols; precompute fix in v6.0.1)

## Filing issues

```bash
gp daemon diagnose
```

Produces an operational dump suitable for attaching to issues. It
collects daemon status, last rebuild log, P50/P99 over the last
hour, RAM use, watcher health. Strip secrets before sharing.

## Honest disqualifications

graphify-plus is not a database, not a security tool, not your IDE,
not your wiki, not real-time. The full list is in the [README](../README.md).

---

**The single bit that matters**: install the hook, set the baseline,
let it run for a week, look at `adoption_rate` and the delta. That
number tells you whether v6.0 worked for you, in your repo, on your
team's actual Claude Code workflow. Everything else in this release
exists to support that measurement.
